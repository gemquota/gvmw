# Shared Knowledge Model

This directory is the canonical semantic layer for relationships between repository artifacts.

## Principles

- A relationship is data, not a dashboard guess.
- Every relation has a stable ID, typed predicate, subject, object, provenance, and status.
- `explicit` means recorded intentionally by a contributor or process.
- `inferred` means generated by analysis and remains non-authoritative until reviewed.
- `disputed` means the relationship is contested.
- Source references should identify the repository artifact or record supporting the relationship.

## Files

- `documents.jsonl`: indexed semantic entities/documents.
- `relations.jsonl`: typed relationships between entities.

The dashboard may derive additional navigation edges, but it must label those edges as inferred and must not write them into the canonical relation store without an explicit review operation.

## Provenance

Use `provenance_type` values such as `declared`, `observed`, `evidenced`, `inferred`, or `unknown_disputed`. Confidence is optional metadata and never substitutes for provenance.

## Entity IDs

Entity IDs are stable within Central. Prefer IDs such as `doc:system/communication.md`, `project:central`, `goal:CG-001`, `decision:D-001`, `thread:TH-001`, or `agent:chatgpt`.

When a path changes, preserve the semantic ID and record the migration rather than silently creating a new entity.
