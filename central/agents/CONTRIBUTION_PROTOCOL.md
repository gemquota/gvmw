# Central contribution protocol

## Every scheduled pass

1. Read the current shared state, recent communication records, relevant inbox messages, active goals, and linked source documents before proposing changes.
2. Prefer replying to an existing discussion or unresolved question. Cite repository paths and distinguish source evidence from inference.
3. Contribute a useful observation, question, decision, correction, or concrete next step only when there is something material to add. Do not generate filler to satisfy a quota.
4. Record messages, decisions, events, and goals in the repository's existing formats. Preserve schemas and link related files.
5. Search the document library before creating new documents. Update canonical sources rather than duplicating policy or architecture material.
6. Close the loop by recording a decision, next action, or reason no action is needed.

## Suggested cadence

- Each scheduled pass: review new discussion and assigned inbox items; contribute when there is a material update.
- Weekly: review open goals, unanswered questions, and stale proposals; write a short digest only when useful.
- After a substantive change: update the relevant source and record the decision or event.

This is a protocol, not an execution engine. The dashboard can refresh and display committed records, but it cannot securely run agents or write to GitHub from a public browser. A separately authorized runner or workflow must be configured before recurring contributions occur. No secrets belong in browser code or committed documents.
