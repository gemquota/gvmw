# MedB v3 — Change Log

## Source basis

v3 is based on the v2 specification and the recovered 86-point adversarial review summary. The purpose is not to increase the number of constitutional slogans; it is to make the existing distinctions traceable to implementation obligations, tests, evidence thresholds, and unresolved decisions.

## Principal changes from v2

1. **86-point traceability:** Adds a point-by-point matrix so review findings cannot silently disappear between analysis and repository changes.
2. **Specification status clarity:** Marks v3 as an adversarial candidate, not a frozen or certified constitution.
3. **Implementation contract:** Defines logical evidence, authorization, and constitutional-event records; separate provenance channels; a pre-operation check; and explicit constraint-composition obligations.
4. **Operational hypothesis boundary:** Specifies separate permissions for storage, retrieval, review, context, personalization, ranking, and action selection.
5. **Suspension contract:** Defines state transitions, dependency propagation, cache/alternate-path checks, restoration evidence, and safe degradation.
6. **Deletion contract:** Requires descendant classification, cache/index/summary/embedding checks, semantic-residue probes, metadata leakage review, and honest boundary disclosure.
7. **Causal lineage:** Requires exposure records and prevents unsupported claims of independent confirmation.
8. **Adversarial tests:** Adds explicit direct, evasive, composition, deletion, suspension, manipulation, hidden-state, and longitudinal cases with expected outcomes.
9. **Mutation sensitivity:** Requires controlled bad mutations to be detected; failure to detect them is a test-suite defect.
10. **Protocol hardening:** Adds preregistration, oracle versioning, positive/negative controls, independence disclosure, and an oracle challenge for unresolved questions.
11. **Constitutional decision register:** Keeps amendment authority, membership boundary, dependence threshold, and consequential feedback open rather than silently resolving them.
12. **Status discipline:** Separates NOT-TESTED and NOT-APPLICABLE from actual outcomes; disallows aggregate PASS from hiding missing required tests.
13. **Longitudinal and sequence controls:** Explicitly includes cumulative limits, model/runtime/ranking/schema/configuration changes, and accumulated history.
14. **Claim limits:** States that documents and test plans are not implementation evidence.

## Deliberately unresolved

- Legitimate Charter amendment authority and procedure.
- Ultimate MedB membership boundary.
- When emergent practical dependence is independently unconstitutional.
- Required response to consequential representational feedback beyond causal marking.
- Exact acceptable retention of deletion-event metadata.
- Some details of trusted-base independence, dependent on implementation and available evidence.

## What v3 does not claim

- That a conforming implementation exists.
- That any test in the suite has been executed.
- That the listed controls are implemented.
- That the v2 review is fully resolved.
- That v3 itself was adopted through a legitimate constitutional amendment procedure.
